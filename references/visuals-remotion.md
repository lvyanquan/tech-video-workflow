# 画面、官方图标与 Remotion

## 工程与依赖

独立建立制作工程，先检查可用 Node.js、浏览器、磁盘、字体及 Remotion 版本。项目已有依赖时遵循锁文件；不要为了追新随意升级。将实际使用的 Remotion 包版本保持一致，并记录安装及渲染命令。

需要底层实现知识时使用 Remotion [官方技能入口](https://www.remotion.dev/docs/ai/skills)。先核对当前技能结构和项目版本，只安装/读取必要内容，不全局铺开第三方工作流。本 Skill 提供内容与制作决策，不替代官方 API 文档。

## 可解释的运动

- 每个场景有可见变化：输入/处理/结果、前后对比、队列放行、字段对齐或状态交接。只更换标题的卡片序列不算机制演示。
- 给重要对象稳定位置和颜色；先出现输入，再展示变化，最后落在收益或边界。避免全屏同时动。
- `useCurrentFrame()` 驱动 `interpolate`/`spring` 等动画。不要依赖实时时钟、CSS 定时动画、未固定随机数或未完成的网络请求。
- [Sequence](https://www.remotion.dev/docs/sequence) 内的帧坐标是局部的；主时间轴为全局帧。字幕、音频、触发点使用同一份排期，不能各自维护偏移。
- 图片、字体等资源准备完成再截图/渲染。音频文件应与清单哈希匹配，渲染时不访问会过期的远程 TTS URL。

## 布局先验证，再全片渲染

横屏 1080p 可从左右约 100px、顶部约 80px 的留白开始设计，底部单独预留字幕区。这是起点，不是所有画幅的硬编码规则。

用合法中文字体，检查中英文混排、数字、小字号以及长标题。先在目标分辨率渲染代表画面，再缩到实际观看尺寸看文字与图标是否仍清楚。不能以 DOM 存在或图片路径正确代替视觉检查。

视觉风格由用户决定。技术视频可以使用简洁矢量、明暗章节交替或手绘图解；不要自动把文章的 Excalidraw 规范强加给所有视频。图解运动不应掩盖正文的技术限制。

## 官方图标

对需要出现的项目建立[素材清单](../templates/asset-manifest.json)：

1. 从官方网站或官方仓库确认原始资源，不从搜索缩略图或未核实图标站直接拿。
2. 记录来源页、资源地址、获取日期、SHA-256、权利/使用条件和本地相对路径。
3. 保留原始比例与配色；深浅底不合适时选择官方变体或调整背景，不自行改绘。
4. 检查像素/矢量质量、裁切、遮挡、字幕覆盖和实际停留时间。页签小图不一定适合全屏放大。
5. 写明在哪个 scene、哪个时间点可见，保存修订前后样张。只有下载没有接入画面，不算完成。

标识用于识别项目，不暗示官方背书。不能用图像生成模型生成“类似官方”的品牌 Logo。新增图标应保留已经确认的图标、字体与版本号格式。

## 渲染兼容性

先做短片试渲染，确认浏览器、字体、声音和编码器都可用，再渲染整片。某台机器出现编码错误不是所有环境的结论。

如果原生编码路径失败，诊断版本和系统兼容性后，可参考官方 [renderFrames](https://www.remotion.dev/docs/renderer/render-frames) 输出完整图像序列，再用兼容 FFmpeg 编码与混音。必须核对起始帧、帧数、帧率和音轨；不能靠 `-shortest` 静默截掉缺失尾段。记录临时帧目录和磁盘预算，只有验收后才清理可再生文件。

不要擅自更新操作系统、安装浏览器扩展、上传云渲染或切换付费服务。替代路径也要执行完整媒体和视觉验收。
