# 修订、验收与交付

## 内容版本与制作轮次分开

维护清楚的版本清单：

| 字段 | 意义 |
|---|---|
| contentBaseline | 用户确认的内容版本及工程快照 |
| edition | 本次唯一交付版本，如 `full-voice-r2` |
| scope | 仅图标 / 仅发音 / 换声 / 内容精简等 |
| changedScenes | 受影响 scene ID 与原因 |
| timingDelta | 旁白、停顿、章节及全片时长差异 |
| validation | 机器校验、视觉抽查、听审分别完成到哪里 |

“使用 V3，忽略 V4”意味着恢复用户认可的 V3 全部内容与图标，再实施本次修订；不能只改文件名。工作目录叫下一轮制作编号，也不能误导用户以为内容采用了被否定的精简版。

原版本和依赖素材保留；所有改动在新目录导出。对内容稿、场景列表、官方图标和版本号格式做差异核查。

## 快修的边界

只补图标时可重渲染受影响场景，但新旧片段应匹配编码、帧率、音轨和时间基准，拼接后仍需完整解码及检查接缝。不能用整片画面缩放误伤字幕。

换声音通常会改变总时长：比较场景数、文稿与停顿再解释为什么变短/变长；提供变化来源，不凭听感断言“没删内容”。

字幕、章节或 cue 发生偏移时，局部替换不能只交付新音频。必要时重渲染全片，保证交付各文件属于同一 edition。

## 分层验收

1. **内容：** 核查目标发布版本、核心收益、限制、显示文本、图中箭头含义及最终文稿差异。
2. **时间：** 实际时长满足当前需求，场景连续，字幕单调不越界、不漏正文，cue 属于正确场景。无配音片的阅读时间不称为声音对齐。
3. **画面：** 每章至少检查进入、中段、退出和关键变化帧，包含所有官方图标出现位置。看字体、遮挡、对比度、裁切和底部字幕；静帧通过不代表运动节奏通过。
4. **声音：** 实际听开场、所有专名/数字、限制语句、转场及修订接缝。确认无漏词、重复、截断、爆音或音乐盖过人声；自然程度需用户确认。未能听到音频时明确标注未听审。
5. **媒体：** 检查视频/音频流、分辨率、帧率、帧数和时长；完整解码，不只读容器头。测量响度/峰值并记录方法；按内容、平台与用户偏好设置目标，不宣称单一数值适用于所有发布渠道。
6. **交付：** 本地文件真实存在且能打开；工程素材引用完整、锁文件和重渲染命令齐全，交付包不含凭据、缓存和内部研究。

机器工具见[时间轴与工具](timing-tools.md)。测试、关键帧抽查、完整解码和全片观看是不同证据，报告中分开写。

## 推荐交付结构

按用户需要选择，不要求每次都导出所有变体：

```text
delivery/<edition>/
  final.mp4
  captions.srt
  captions.json
  narration.md
  narration.wav
  chapters.txt
  timeline.json
  assets-and-sources.md
  qa-summary.md
  project/                 # 源码、锁文件、获准分发的素材
```

提供无旁白版时，说明是“仅去人声、仍有音乐”还是完全静音；如果要后期替换声音，按需另给纯旁白和音乐音轨。不要把不同音轨版本混淆成同一成片。

明确给出绝对本地路径、新旧版差异、合成声音声明与未完成验证。用户问“图片在哪里”时应定位原始资源和实际使用版本，而不是只给工程根目录。

## 对外上传

本地交付不自动授权发布。GitHub、网盘、在线文档或视频平台上传需明确目标、文件清单、覆盖范围及许可，遵守宿主的预览和确认要求。

公开 Skill 仓库只保留可复用原创指引、模板、脚本和必要出处；不要整包提交旧项目、字幕、签名 URL、内部截图、系统字体或 TTS 请求记录。旧的发布授权不自动涵盖新的上传。
