# 从制作迭代中提炼的经验

以下是流程经验，不是旧项目、原文档或音视频的公开归档。示例中的版本称呼仅帮助理解如何决策，不应写死进未来项目。

| 用户反馈 | 应采取的动作 | 不能偷换成 |
|---|---|---|
| “版本号不要写成中文读音” | 显示稿、字幕和画面统一数字格式，TTS 层独立处理读法 | 取消发音修正，或把谐音写回字幕 |
| “没有看到官方图标” | 核查来源、接入场景、显示大小/背景，并交付对应样张和时间点 | 只指出下载目录里已有文件 |
| “五分钟内讲完” | 精简重复叙事，保留边界，重做配音和时间轴 | 整体倍速或删掉关键限制 |
| “不用五分钟限制，只要原完整版” | 恢复认可的内容基线，移除旧标题与硬上限 | 继续拿精简稿换个文件名 |
| “AI 味太重，想要温柔专业女声” | 调整自然段与表达，生成小范围对照试听，确认后做全片 | 保证某音色一定像真人 |
| “一个多音字读错了” | 尝试不改变意思的表达，再试听相关段 | 只改文字，不重生成声音 |
| “换到阿里云，北京” | 确认地域/模型/凭据匹配，重新授权试听 | 复用其他服务 Token 或直接批量付费 |
| “某时间点的 Paimon 发音应改为派蒙” | 定位当前版本片段，仅改 TTS 读法并校验时间变化 | 把正式名称和 Logo 全部中文化 |
| “为什么少了十几秒” | 对比场景、文稿、段落语速和留白，给出证据 | 没比较就说没删或确实删了 |
| “图片/新旧文件在哪” | 给明确版本目录、资源路径、对应画面与差异 | 只给一个含多版混杂的输出目录 |

旧设计文件可能被后续精简版更新。恢复完整版时应结合工程快照、场景清单和用户确认记录，不依赖单个最新设计文件。

## 一次修订的最小记录

```text
内容基线：full-v3
本次版本：full-v3-voice-r2
修改范围：scene-benefit 的一个专名读法
显示文本：不变
原始片段：旧文件及哈希
新片段：新文件及哈希、请求参数指纹
时间变化：实测后填写，不预填为 0
影响：后续字幕、章节、动画 cue、纯旁白及成片
验证：接缝试听 / 图标样张 / 完整解码分别记录
```

这些记录写入项目自己的制作目录，不上传包含个人路径、账户信息或私密素材的原始日志。
